# T4 — postgresql: a child's NOT NULL under `INHERITS` is applied to the parent

**Status:** drafted, not filed. Against sqlc v1.31.1 (`a95e91d70`).

**Title.** postgresql: `INHERITS` — a child table redeclaring an inherited
column as NOT NULL marks it NOT NULL on the PARENT too

## Reproduction

Schema, verbatim from sqlc's own
`internal/endtoend/testdata/ddl_create_table_inherits`:

```sql
CREATE TABLE party (party_id uuid PRIMARY KEY, name text NOT NULL);
CREATE TABLE person (first_name text NOT NULL, last_name text NOT NULL) INHERITS (party);
CREATE TABLE organisation (legal_name text) INHERITS (party);
CREATE TABLE llc (incorporation_date timestamp, legal_name text NOT NULL) INHERITS (organisation);
```

Query `SELECT * FROM organisation;` — sqlc's IR gives `legal_name`
`not_null: true`, but `organisation.legal_name` is declared with no constraint.
The NOT NULL belongs to `llc`, its child.

PostgreSQL:

```sql
INSERT INTO organisation (party_id, name, legal_name)
VALUES ('11111111-1111-1111-1111-111111111111', 'acme', NULL);   -- accepted
SELECT * FROM organisation;
-- → ['11111111-1111-1111-1111-111111111111', 'acme', null]
```

Deleting `llc` from the schema makes sqlc report `legal_name` nullable — which
isolates the direction of the leak: the constraint flows child to parent.

## Expected

`organisation.legal_name` nullable; `llc.legal_name` NOT NULL. Constraint
merging under `INHERITS` runs parent → child only.
