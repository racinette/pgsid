# T5 — postgresql: `SELECT * FROM f(...)` collapses when `f` is `RETURNS TABLE`

**Status:** drafted, not filed. Against sqlc v1.31.1 (`a95e91d70`).

**Title.** postgresql: star expansion over a `RETURNS TABLE (...)` function
yields one column named after the function instead of the table's columns

## Reproduction

Schema, verbatim from sqlc's own
`internal/endtoend/testdata/func_star_expansion`:

```sql
create function test_func_select_blog(in p_id int)
    returns table (id int, name text, created_at timestamp, updated_at timestamp) AS $$
BEGIN RETURN QUERY
    select id, name, created_at, updated_at from blog where id = p_id;
END;
$$ language plpgsql;
```

Query `select * from test_func_select_blog($1);`

sqlc's IR: **one** column, `test_func_select_blog`, `not_null: false`.

PostgreSQL: **four** columns. Two independent readings:

```
PREPARE p AS select * from test_func_select_blog($1);
SELECT result_types::text[] FROM pg_prepared_statements;
  → {integer,text,"timestamp without time zone","timestamp without time zone"}

EXPLAIN (VERBOSE) select * from test_func_select_blog(1);
  → Function Scan on public.test_func_select_blog
    Output: id, name, created_at, updated_at
```

## Isolation

Only `RETURNS TABLE` is affected; `OUT` parameters and `RETURNS SETOF <table>`
both expand correctly:

```
select * from f_table($1)   -- returns table (id int, name text)
  → 1 column  'f_table'                        ← wrong
select * from f_out($1)     -- OUT o_id int, OUT o_name text
  → 2 columns 'o_id', 'o_name'                 ← right
select * from f_setof($1)   -- returns setof blog
  → 2 columns 'id', 'name'                     ← right
```

## Root cause

Two lines, both in the `*ast.RangeFunction` branch of `Compiler.sourceTables`
(`internal/compiler/output_columns.go`, branch at line 523):

1. `catalog.Function.OutArgs()` (`internal/sql/catalog/func.go:42-50`) matches
   only `ast.FuncParamOut`. A `RETURNS TABLE` parameter converts to
   `ast.FuncParamTable` (`internal/engine/postgresql/convert.go:22`), so
   `fn.Outs` is empty for exactly these functions.
2. Even when `fn.Outs` is populated, the block that follows REPLACES the
   columns rather than skipping — line 576 appends, line 584 overwrites:

```go
if len(fn.Outs) > 0 {
    for _, arg := range fn.Outs {
        table.Columns = append(table.Columns, &Column{Name: arg.Name, DataType: arg.Type.Name})
    }
}
if fn.ReturnType != nil {
    table.Columns = []*Column{        // <- unconditional overwrite
        {Name: colName, DataType: fn.ReturnType.Name},
    }
}
```

That the observed arity is 1 rather than 0 confirms `fn.ReturnType` is non-nil
for a `RETURNS TABLE` function, so this is the branch taken.

## Suggested fix

Include `ast.FuncParamTable` in `OutArgs()` (or add a `TableArgs()` beside it),
and make the `ReturnType` block an `else if` so a function with OUT/TABLE
columns keeps them.
