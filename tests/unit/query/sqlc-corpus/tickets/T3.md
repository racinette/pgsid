# T3 — postgresql: `CREATE TABLE … AS SELECT` copies NOT NULL

**Status:** drafted, not filed. Against sqlc v1.31.1 (`a95e91d70`).

**Title.** postgresql: `CREATE TABLE x AS SELECT * FROM y` carries `y`'s NOT
NULL constraints into `x`

## Reproduction

Schema, verbatim from sqlc's own `internal/endtoend/testdata/create_table_as`:

```sql
CREATE TABLE foo (val text not null);
CREATE TABLE second_table AS SELECT * FROM foo;
```

Query:

```sql
-- name: GetFirst :many
SELECT * FROM second_table;
```

sqlc's IR: `val` `not_null: true`. PostgreSQL disagrees — `CREATE TABLE … AS`
copies column names and types only, never constraints:

```sql
INSERT INTO second_table (val) VALUES (NULL);   -- accepted
SELECT * FROM second_table;                     -- → [null]
```

## Expected

`val` nullable.

## Do not overshoot

`LIKE` is the contrast, and sqlc gets it right today. `CREATE TABLE liked (LIKE
foo)` DOES copy not-null constraints — they are not among the things
`INCLUDING CONSTRAINTS` governs — so only the `AS SELECT` path should change.
Measured on v1.31.1: `SELECT * FROM liked` reports `val` NOT NULL, correctly.
