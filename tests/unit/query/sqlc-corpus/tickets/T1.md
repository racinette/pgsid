# T1 — postgresql: every function call's result is inferred NOT NULL

**Status:** drafted, not filed. Against sqlc v1.31.1 (`a95e91d70`).

**Title.** postgresql: function and aggregate results are always
`not_null: true` (`ReturnTypeNullable` is never set for the postgres engine)

## Body

`internal/compiler/output_columns.go:316` decides a function call's
nullability as

```go
cols = append(cols, &Column{
    Name:       name,
    DataType:   dataType(fun.ReturnType),
    NotNull:    !fun.ReturnTypeNullable,
    IsFuncCall: true,
})
```

`catalog.Function.ReturnTypeNullable` is only ever set in
`internal/engine/dolphin/stdlib.go` and `internal/engine/sqlite/stdlib.go`.
Nothing in `internal/engine/postgresql` sets it, and `sqlc-pg-gen` does not
emit it — so for PostgreSQL the expression is `!false` for every resolved
function, and every function result is NOT NULL.

The flag was added in #1294 (2021-11-19) to fix MySQL's `GROUP_CONCAT`, which
returns NULL over an empty group, and extended to SQLite in #1712. PostgreSQL
has the same problem for every aggregate.

## Reproduction

```sql
CREATE TABLE t (
  id bigserial PRIMARY KEY,
  nn numeric NOT NULL,
  nl numeric,
  g  text NOT NULL
);
```

sqlc's IR (`json` codegen, `not_null` per column):

```
SELECT SUM(nn) FROM t;                                     → sum       NOT NULL
SELECT SUM(nl) FROM t;                                     → sum       NOT NULL
SELECT AVG(nn), MIN(nn), MAX(nn), COUNT(nn), COUNT(*)      → all five  NOT NULL
  FROM t;
SELECT g, SUM(nn), AVG(nl) FROM t GROUP BY g;              → all three NOT NULL
SELECT bool_and(nn > 0), string_agg(g, ','), array_agg(nn) → all three NOT NULL
  FROM t;
```

Against an EMPTY `t`, PostgreSQL returns NULL for every one of these except the
two `COUNT`s:

```
SELECT SUM(nn) FROM t;   →  [null]
```

Non-aggregate calls have the same shape:

```sql
CREATE TABLE foo (a int, b int);
SELECT abs(a) FROM foo;   -- sqlc: NOT NULL; PostgreSQL with a = NULL: NULL
```

## Expected

`COUNT` is NOT NULL. Every other aggregate is nullable — an ungrouped aggregate
over zero rows returns one row of NULLs, and `AVG`/`SUM` skip NULL inputs so an
all-NULL group is NULL too. A non-aggregate call is nullable unless the
function is strict AND its arguments are all non-null AND the function is known
total over them.

## Suggested fix

Populate `ReturnTypeNullable` for the postgres catalog: `false` for `count`,
`true` for the other aggregates; for scalar functions derive from
`pg_proc.proisstrict` plus the caller's argument nullability. `proisstrict` is
already available to `sqlc-pg-gen`.

## Cases in sqlc's own testdata that this changes

`accurate_cte`, `func_aggregate`, `min_max_date`, `sum_type`,
`valid_group_by_reference`, `pg_advisory_xact_lock`.

Two of those (`pg_advisory_xact_lock`'s pair) only produce a NULL under a NULL
parameter binding, which sqlc's own IR declares out of contract — recorded in
their `adjudication.json`, and not what the fix rests on.
